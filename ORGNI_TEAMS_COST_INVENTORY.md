Orgni on Microsoft Teams: cost inventory and Engineering investigation

Research date: 30 September 2026. This inventory follows the request to identify costs first, then choose which costs to reduce. No deployment or purchasing decision has been made.

The repository already implements a custom Teams bot inside the TypeScript/Express API. The root `main.py` is a placeholder. A new chatbot platform is not inherently required. Teams transport can have zero additional charge; operating Orgni still involves hosting, data, AI usage, and Engineering work.

Public prices below are USD benchmarks, not an Orgni quotation. No Azure billing export, Microsoft license inventory, provider invoice, production environment configuration, or traffic measurements were available. A service appearing in source code or the architecture document does not establish that it is deployed or being billed. Taxes, currency conversion, discounts, commitments, and support contracts must be taken from the actual account.

For hosting, Container Apps Consumption includes 180,000 vCPU-seconds, 360,000 GiB-seconds and 2 million HTTP requests per calendar month per subscription. At a hypothetical 0.25 vCPU/0.5 GiB, both compute allowances equal 200 aggregate replica-hours. This calculation assumes the full grant remains available. It is not a continuously running free server: startup, time before scale-down and other apps consume the allowance. Databases, logs, registry and other services have separate meters. [Container Apps billing](https://learn.microsoft.com/en-us/azure/container-apps/billing).

For AI, an illustrative 10,000 successful Opus 5 calls, each with 1,000 uncached input tokens and 400 output tokens, cost `10,000 × ((1,000 × $5 + 400 × $25) / 1,000,000) = $150`. This is an example, not measured Orgni usage. The code caps output at 400 tokens per call and requests adaptive thinking with low effort; thinking consumes output budget too. Count retries/additional calls and actual provider-reported token usage when budgeting. Without an Anthropic key, model API cost is zero but replies use templates. [Opus pricing](https://platform.claude.com/docs/en/models/opus-5/overview), [thinking and cost](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost).

If prompt caching is enabled later, Opus 5 prices per million tokens are $6.25 for a five-minute cache write, $10 for a one-hour write and $0.50 for a cache read. These categories replace ordinary input billing for those tokens; do not count them twice. A paid Claude web subscription does not include ordinary API billing. [Cache pricing](https://platform.claude.com/docs/en/about-claude/pricing), [subscription/API distinction](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-do-i-have-to-pay-separately-to-use-the-claude-api-and-console).

Engineering should account for these concrete implementation tasks in any setup estimate:

1. Preserve the existing `/api/teams/messages`, tenant-resolution logic, request engine and Adaptive Cards. The relevant files are `artifacts/api-server/src/teams/{adapter,bot,manifest,oauth}.ts` and `src/routes/teams.ts`; no Python chatbot rewrite is implied.
2. Replace unsupported BotBuilder dependencies with a supported SDK when preparing production rollout. Teams SDK fits the current Teams scope; its migration work is a setup/maintenance cost. [Microsoft SDK guidance](https://learn.microsoft.com/en-us/microsoftteams/platform/legacy-tools-sdks).
3. Correct `MICROSOFT_TEAMS_SETUP.md`, `.env.example` and configuration defaults that recommend a new Azure `MultiTenant` bot. Current guidance requires a supported bot type such as `SingleTenant`; Entra sign-in audience is a separate setting and can still allow other organizations. Keep the bot's home registration tenant distinct from each customer's tenant. Validate installation and replies in a second tenant. [Microsoft registration guidance](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/how-to/authentication/add-authentication).
4. Finish production web authentication and tenant-link verification. The callback currently trusts query-string `tenant` after checking signed state; state does not authenticate that returned tenant. Microsoft explicitly warns against using this parameter for authentication/authorization. Budget a verified sign-in/tenant-ownership flow, administrator authorization and replay protection. Separating web customer authentication from bot credentials is an Engineering option, not a universal Microsoft requirement. [Admin-consent protocol](https://learn.microsoft.com/en-us/entra/identity-platform/v2-admin-consent).
5. Validate runtime dependencies and persistence before estimating a small container. `src/index.ts` starts Python document intelligence if `DOCUMENT_INTELLIGENCE_URL` is absent, while the API Dockerfile does not include that Python service. Configure a real external service or fix packaging, then measure memory and startup behavior. Include its compute cost. Use Postgres for durable Teams identity and conversation data.
6. For a pilot, test authenticated inbound messages, private chat, channel mentions, card approvals, unauthorized/unlinked tenants, replayed messages, restarts and cross-customer isolation. Test cold starts if considering scale-to-zero. Existing unit tests are not proof of a deployed Teams integration.

To turn the inventory into an actual monthly total, collect the last 30-90 days of provider spend by resource/service; Microsoft subscription SKUs and assigned seats; live host, region and resource sizes; AI model and token usage; request volume and peak concurrency; storage/OCR volume and retention; support commitments; and setup quotations. Mark each line as already paid/shared, incremental for Teams, or optional/planned. Ask for invoice totals or cost exports, not credentials.

Use two totals: **total Orgni operating cost** and **additional cost attributable to Teams**. The latter is new licenses plus incremental compute, AI, data, networking and support. Removing Teams would not necessarily remove the shared platform bill. Add one-time setup separately; amortize it only when comparing total ownership cost over an agreed period. Avoid adding Studio's internal AI charge and the same model usage twice, but count an external Orgni API/model call if a Studio agent actually invokes it.

This investigation identifies credible zero-additional-charge Teams transport paths. Which cost to reduce, and whether any migration pays for itself, should be decided after the account-specific amounts are attached to this inventory. Only this research document was added; no runtime configuration, subscription or deployment was changed, and no live Teams test was performed.
